# newonott.in — context prompt

Paste everything below into a fresh session to bring it up to speed.

---

You are working on **newonott.in**, an Indian OTT release calendar and search
site. The goal, stated by the owner: *when someone searches Google for anything
about a movie or show, newonott should be the result that comes up.*

## What the site is

A release calendar answering "what is new on Indian streaming this week" and
"where can I watch X in India", covering every major platform plus cinema
releases. The competitive set is JustWatch, Binged, IMDb and Wikipedia. The
realistic wedge is what Google currently serves badly: Indian regional OTT
release dates — "when is <Malayalam film> coming on OTT", "where to watch
<Telugu film> in India" — rather than head-on competition for "Inception cast".

## Stack

- React + TypeScript + Vite single-page app.
- **Prerendered SEO pages** generated by `scripts/build-seo.mjs` at build time.
  Every indexable page ships as real HTML; the SPA hydrates over it.
- **Cloudflare Workers** (`worker/index.js`), `run_worker_first: true`,
  `not_found_handling: single-page-application`. The Worker owns URL
  normalisation, `/api/search`, `/api/title`, `/api/person`, `/api/browse`, an
  image proxy at `/img/`, and `/api/watchdog`.
- **D1** holds the newsletter subscriber list only. There is no releases table;
  all content is JSON built at deploy time.
- **TMDB** is the only content source. Queries use `watch_region=IN` plus
  `with_watch_providers` from the registry in `src/data/platforms.ts`
  (23 Indian platforms, 40 provider ids).
- Deployed by Cloudflare's dashboard integration off each push; a GitHub Actions
  workflow runs the same build plus all gates and verifies what is actually live.

## Data pipeline

- `scripts/fetch-releases.mjs` — the weekly calendar feed.
- `scripts/fetch-catalogue.mjs` — the back catalogue. Two passes per language: a
  rating pass (`sort_by=vote_average`, above a per-language vote floor) and a
  popularity pass (`sort_by=popularity`, floor a fifth of that). Provider
  attribution costs one call per title.
- `scripts/archive.mjs` — a permanent record, so a title that drops out of TMDB
  keeps its page. `changedAt` on each row feeds sitemap `lastmod`.
- Runs on a schedule via `.github/workflows/refresh-releases.yml`, gated on the
  full eval suite: a bad refresh is not committed.

## How SEO is implemented

- **2,239 prerendered pages**: 2,172 title pages (`/ott-release-date/<slug>`),
  20 platform, 17 language, 10 collection/genre, 11 week, 6 month, 2 lens, root.
- **Structured data** per title page: `WebSite`, `BreadcrumbList`, and
  `Movie`/`TVSeries` carrying name, datePublished, description, image, genre,
  inLanguage, duration, actor, a `WatchAction` naming the platform and India as
  eligible region, and `aggregateRating` on 1,257 pages (58%) — emitted only
  where the score clears 50 votes and 9.5, matching the thresholds the UI uses
  to grey out thin scores, and always attributed to TMDB.
- **Title tags** front-load the platform, because it is the answer to the query.
  Median 61 characters; the platform falls past the ~57-character truncation
  point on 14 of 2,172 pages (was 953).
- **Internal linking**: every title page links six siblings, chosen as
  neighbours on a rating-sorted ring within its language, so inbound degree is
  uniform rather than concentrated. 0 single-linked pages, 14.9 inbound links on
  average (was 539 and 3.0).
- **Sitemap** of all 2,239 URLs with `lastmod` from the archive's `changedAt`,
  not the build date. `robots.txt` disallows `/api/` and `/diag` only.
- **URL normalisation** in one step: lowercase and trailing-slash removal
  together, so no page costs two redirects; percent-escapes and file extensions
  are left alone.

## Search (the site's own)

`/api/search` proxies TMDB with three fallbacks, in order: the query as typed,
then with noise words and bare years dropped, then the longest remaining token
alone. If the result set is empty **or contains nothing actually titled what was
asked for**, it retries across romanisation equivalence classes (schwa a/u,
doubled consonants, ph/f, v/w, z/j, ksh/x, final vowel) — because an Indian
title has no single correct Latin spelling. A variant wins only if a result is
titled one of the spellings, and the response reports `relaxedTo` so the reader
is told which spelling was used.

260 impressions/day from those 9 is the encouraging signal — the pages that do

## Catalogue coverage

1,804 titles. Per original language:

```
hi 295   ta 207   en 198   ml 192   te 191   ja 175   ko 128
es 126   fr 115   de  68   bn  46   kn  37   mr  15   pa  11
```

South Indian coverage roughly tripled recently (Telugu 63→191, Malayalam
58→192, Tamil 113→207) by recalibrating per-language vote floors: they were
absolute TMDB vote counts, and TMDB's voting population is Western, so a 60-vote
floor kept 4.4% of Tamil's titles while a 400-vote floor kept 10% of Japanese's.
Floors are now bisected per language against a target, clamped at a minimum of
25 votes below which a score is noise.

Kannada, Bengali, Marathi and Punjabi did not move and appear genuinely
exhausted at the current query. The untested lead is the free and ad-supported
monetisation tiers, measured as worth ~4% at high vote floors but never
measured at low ones.

## Quality gates

Everything runs in CI on each push and blocks the refresh:

```
npm run eval          44 checks — SEO, honesty, reachability, crawl rules
npm run test:worker   99 checks — the edge: search, redirects, caching
npm run e2e          496 checks — real browser, 13 viewport widths
npm run test:rail     59    npm run test:search  26
npm run test:tmdb      8    npm run test:fetch   16    npm run test:windows 10
```

The eval suite enforces rules that are worth knowing because they encode
mistakes already made: no page may claim a streaming date it never observed; no
two pages may share a title or description; every title page must be reachable
from another page; a guessed platform must be marked as a guess; sitemap and
robots.txt must agree; no page may assert a rating more confidently than it
displays it.

## Working principles in this codebase

- Comments explain *why*, usually citing the incident that caused the rule.
- Measure before changing; several plausible theories about coverage were wrong
  and were only caught by measuring (the platform registry, then the flatrate
  filter, both ruled out before the vote floors turned out to be the cause).
- A confident wrong answer is worse than an empty one — this decides several
  behaviours in search and in structured data.
- A check that can hide a worse check must run last.
- Gates are proven by breaking them deliberately and watching them fail.
